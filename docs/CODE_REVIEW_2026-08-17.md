# 全コード監査 2026-08-17

## 範囲と方法

廃止対象だった市場AI要約機能を除去した後の現行Reflexコードを、データ取得、分析サービス、Context/State、UI、AI入力の順に確認した。履歴用 `progress.md`、`docs/archive`、`docs/ui-audit` は現行仕様の残存参照判定から除外した。

確認対象は `src`、`frontend`、`tests`、現行設定、依存関係、現行仕様書。欠損の0埋め、古いデータ、非同期競合、暗黙の高コスト取得、例外処理、timeout/cache、型境界、秘密情報、未使用コード、テストを優先した。

## 今回追加した機能改善

一般的なウォッチリスト、任意条件スクリーナー、変化通知、保存基盤は追加していない。比較資料から本アプリへ取り込んだのは、テーマの浮上、テーマ内リーダー、仕掛け準備、根拠追跡の4点だけである。

| 不足していた判断 | 実装 |
|---|---|
| テーマの浮上 | 1週間・1か月・6か月の中央値、期間別順位、価格・市場相対強度・資金注目度proxy・広がりの100点、取得率、順位加速 |
| テーマ内リーダー | 監査済み登録代表と、一次資料で検証したGemini登録外探索を統合。市場比とテーマ中央値比の20日・63日相対強度、重複テーマ統合 |
| 仕掛け準備 | Stage 2の7条件、VCP、ATR収縮、節目距離、RVOL、4 ATR過熱除外 |
| ファンダメンタル裏付け | テクニカル通過後の最大15社だけを3並列取得し、55点以上、40～54点、40点未満、取得率不足を分離。主候補は70対30で統合 |
| 根拠の追跡 | 検索引用、候補由来、100点内訳、7条件、候補理由、次に確認する条件、無効化条件、取得時刻、使用量、未検証・確認待ち・除外理由 |

## 残課題

| 優先度 | 根拠・影響 | 実装順 | 今回見送った理由 |
|---|---|---|---|
| P2 Large | 一部の旧分析関数は外部取得失敗をログやUI警告へ集約せず、任意入力の欠落として継続する。全経路を一度に変更すると表示契約への影響が大きい | 1. `FetchResult`未対応関数を利用画面別に列挙 2. optional/requiredをmanifestへ追加 3. Stateへ警告集約 4. live smoke | 新機能とRecap廃止の範囲を超える横断変更。現行の必須結果は既存検査で保護されている |
| P2 Large | JPテーマ中央値の個別株Entry Frameworkは最大5 peerを個別取得する互換経路が残る | 1. テーマOHLCV batch providerを共通化 2. Entry Frameworkへ注入 3. cache/partial契約追加 | provider所有権とStock分析入力の変更が必要 |
| P3 | Theme画面はカード表示で、TradingView型のヒートマップではない | 候補機能の利用実績を確認後、既存ランキングデータだけを使う軽量可視化を検討 | 視覚化より、根拠と欠損の明示を優先 |

秘密値らしい固定文字列、追跡済み `.env` / key / pem は検出しなかった。ネットワーク実データと動的ブラウザのPC/モバイル視覚確認は、ローカル決定論的リリースゲートとは別枠で扱う。
