# 投資リサーチUIの再設計・受入記録

実施日：2026-10-10〜11。対象はローカルCodex投資リサーチのダッシュボードと更新入口。ユーザーの承認した「市場→テーマ→銘柄」「グラフ中心＋比較表」「要点と重要な弱点だけ」を実装した。以前の固定レイアウトに関する記録は、この表示設計で更新する。

## 調査から採用した原則

| 原則・一次資料 | この画面への適用 |
| --- | --- |
| 数量は長さと位置で比較する。[NN/g: dashboard perception](https://www.nngroup.com/articles/dashboards-preattentive/) | 指数は線、相対成績と乖離は0基準の横棒、価格位置と評価幅は直線上の位置で表示。数値も併記する。 |
| 最初に必要な機能を示し、詳細を段階的に開く。[NN/g: progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | 全文・取得手順・計算過程を初期表示から外す。要点、欠損、前回値、重要な条件未達は該当値の近くに残す。 |
| 共通属性を行・列で比較し、数値を整列する。[GOV.UK: table](https://design-system.service.gov.uk/components/table/) | テーマは単一表。数値右寄せ、桁幅統一、期間定義は共通ヘッダー。構成銘柄はその行の直下に展開する。 |
| 色以外でも情報を識別でき、必要な図形の識別を確保する。[W3C: non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) | 数値・状態語・0基準・線種・選択表示を併用。キーボードで日付と系列値を読み取れる。主要文字は14〜15px、補助・チャート文字は12px。 |

適用順序は、目的と情報の優先順位→比較方法→操作導線→文字・余白→実データと小画面の検証。情報量を増やす装飾や、新しい総合点は追加しない。

## 実装結果

- **総覧**：日米指数の推移、6つの市場観測、順位と同じ定義のTop5横棒。共通比較が成立しない場合でも、有効な単独指数は表示する。TOPIX代理系列の欠損を日経平均の欠損として扱わない。
- **市場**：指数とMA乖離・20営業日の高安位置、参加範囲、テーマ、金利・信用のbp変化、為替・原油・VIX、公式予定。接続分析は実値と食い違いを短文で示す。全観測・出典と既存29項目は詳細に保持。
- **テーマ**：順位・テーマ・相対成績の棒・騰落率・代表3銘柄・取得率を同じ行で比較。検索／期間／方向／順位／数値ヘッダーの並べ替えと複数行展開に対応。観測期間が共通期間と異なる行には例外日付を表示。
- **銘柄**：「価格・条件」を初期表示し、価格／MA／出来高とStage2・相対強度・VCP・出来高・成長・Entryを並べる。初期選抜値以外のStage2／Entryの未成立・判定不能も隠さない。「成長・事業」「企業価値」「資料・計算」に残る全分析を配置。
- **企業価値**：手法別に3ケースと株価を同じ直線上で比較し、通貨、株価日、会計期末、主要仮定を併記。部分評価・未算定は元の状態を保持。原資料・全入力・逆算は展開。
- **導線**：総覧→テーマ→保存銘柄は2クリック。戻る操作は検索、期間、数値並び順、展開状態を保持。未保存銘柄は保存済みのテーマ内成績とCodexへの依頼文を表示。
- **確認事項・データ**：取得上の問題や食い違いを集約。正常取得の補足は原因欄へ流さない。全入力と診断、操作方法、一般的な説明は開いて確認する。
- **更新入口**：重複したタイトル・全体留保・操作説明を縮小し、更新設定は折り畳む。内部画面は一つのスクロールで操作。明暗を親子で同期する。

計算、金融モデル、取得対象、保存JSONの意味は維持。唯一の取得状態の契約修正は、正常な`reason`を`note`に置き、`error`を失敗等に限定したこと。古い保存結果も表示側で正常補足と失敗を区別する。`embedded`はHTML表示だけの任意引数で、元の保存形式を変更しない。
